# Handoff: Adopt skal v0.5.0 in Crucible

**Date:** 2026-09-16
**skal release:** v0.5.0 — https://github.com/gametheory-school/skal/releases/tag/v0.5.0

---

## Context

skal v0.5.0 shipped three fixes that delete Crucible-side workarounds documented in the v0.5.0 backlog (`skal/docs/handoffs/2026-09-16-crucible-skal-0.5.0-adoption.md`). This prompt drives the adoption work: delete the workarounds, verify the engine now handles them, and update the spec's Non-Goals if anything was cut.

---

## What shipped

### §1 — Validated card renders option labels, not raw values

**Before:** `coach.nudge` confirmation showed a coachee UUID and `coachee_struggling` instead of the coachee's name/email and "Support — struggling".

**Now:** ActionCard resolves choice field values to their option labels via the FieldSpec `options`. No engine API change — `_resolvedFieldMeta` stays private.

**Crucible action:** None required. Verify in smoke test: `coach.nudge` confirmation shows human-readable labels.

---

### §2.1 — Select-time permission gate

**Before:** Mode-blocked skills opened their ActionCard and only failed on Submit. Crucible worked around this with `routeWithGate` in `SkalShell` — duplicated gate logic that belongs in skal.

**Now:** `selectSkill()` runs the compose-time permission check before `prepare()` — a denied selection never fetches data or renders a card. New public `canSelect(skillId): Promise<boolean>` for command-palette filtering / route-time gating (no state transition, safe in render paths). `routeInput` inherits the gate (funnels through `selectSkill`). Dispatcher re-check untouched as defense-in-depth.

**Crucible action:**
1. **Delete `routeWithGate`** from `SkalShell` (or wherever it lives — search for `routeWithGate` in the Crucible codebase).
2. **Replace with `canSelect`** where palette filtering is needed (command bar, skill list). Example:
   ```ts
   const allowedSkills = await Promise.all(
     skills.map(async (s) => ({ skill: s, allowed: await engine.canSelect(s.id) }))
   )
   const visibleSkills = allowedSkills.filter((x) => x.allowed).map((x) => x.skill)
   ```
3. **Verify:** mode-blocked skill never opens its ActionCard — direct `selectSkill` call and `routeInput` both land in `failed` with the denial message.

---

### §2.3 — Zero-option choice downgrade to text input

**Before:** All five Crucible skills' `prepare` hooks defensively downgraded failed fetches to `inputType: 'text'` — five copies of the same pattern. A zero-option required choice field showed "No options available" error with no path forward.

**Now:** Choice fields with empty or undefined options downgrade to `inputType: 'text'` at spec-build (`specInputType` in `src/fields/validate.ts`). The engine handles this automatically. A required zero-option field now surfaces its normal Zod missing-field error after submit (like any text field).

**Crucible action:**
1. **Delete defensive `inputType: 'text'` downgrades** from all five skills' `prepare` hooks. Search for patterns like:
   ```ts
   catch {
     return { ...fieldMeta, template_id: { inputType: 'text', label: 'Template' } }
   }
   ```
   and remove the downgrade — just let the error propagate or return the original fieldMeta unchanged.
2. **Verify:** `session.start` fallback smoke test (from the spec's validation checklist) — when template fetch fails, the field renders as a text input, not a dead dropdown.

## Spec Non-Goals

The skal spec's Non-Goals section (`docs/specs/skal-skills-spec.md:233-239`) deferred to the v0.5.0 backlog doc. Now that v0.5.0 shipped:
- §1, §2.1, §2.3 are **done** — delete from the backlog doc (or mark as adopted).
- §2.2 (`setActor` / actor mutability) is **deferred to design review** — record in the spec's Non-Goals with the reason: "lifecycle semantics (in-flight actions) deserve a decision, not a rush."
- The feature deferrals table in the backlog doc (§3) stays as-is — those are still out of scope.
